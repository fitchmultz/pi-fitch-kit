# Development and validation

## Validation

```bash
npm ci --ignore-scripts
npm run check:compat
```

- `npm run check:compat` reuses `check` plus `smoke` against the actually installed host graph. The locked official development cohort and supported floor are 1.4.0, not CI qualification targets. CI resolves the latest stable official cohort and maintained Fitch runtime's current `main` once per run, then freezes that version and full commit SHA through every build and qualification lane. Both hosts run on Ubuntu with Node 24 and 26 and on macOS with Node 24; optional Fitch runtime capabilities are detected, not required. The compatibility runner selects independent official/Fitch SDK, declaration and CLI graphs; lifecycle checks use the manifest's bundled bin, never Pi from PATH. This does not install the full setup-manifest composition or run paid providers.
- `npm run check` type-checks the bundled extensions, then runs its checks in parallel through Node's test runner. They exercise the image guard boundary, the fast toggles, session naming, the paged reader, and writer commands, and validate unpinned package sources, manifest resources, package metadata alignment, the absence of retired patch and duplicate surfaces, the settings example's model, retry, and compaction consistency, and that every enabled or context-window route is manifest-managed with room for the configured compaction reserve and recent context. It also runs the validator against invalid manifest and compaction inputs; policy values live in the manifest and settings example rather than a second frozen validator table.
- `npm run regression:clean-footer` loads the real footer with an offline SDK session. It checks file-wide names and cache hit rates across redraws, append, rename, branch extraction, reload, and new sessions; live context, model, theme, and wrapping stay fresh. It asserts zero history reads on 100 unchanged redraws before persistence and after a real offline response replaced by a later `message_end` handler, and retains cold recovery of legacy footer preferences. An optional host-root argument supports focused read-only SDK probing, not declaration qualification.
- `npm run regression:fast-mode` verifies real serialized requests with fake fetches: Anthropic speed/beta atomicity and gateway dispatch, OpenAI/xAI priority, exact Astra Ultrafast routing and exclusions, shared/session precedence, native persistence and fork isolation, startup validation across factory recreation, cost notices, footer eligibility, and watcher cleanup.
- `npm run regression:session-name` verifies naming, metadata injection, protected identities, single ownership during migration, and serialized prompt-prefix stability and native session lifecycle behavior.
- `npm run regression:paged-reader` checks bounded Markdown pagination, native fullscreen pointer and regular keyboard controls, local-only draft saves, explicit feedback context and duplicate prevention, reply linkage/fallback, immutable revisions, and file-backed cursor recovery. An offline SDK fixture proves busy-session delivery, direct-abort cancellation without a ghost send, and final-text correlation using a faux provider; no paid request is made.
- `npm run regression:write-prompt` verifies provider/model/thinking inheritance, full and partial overrides, configuration errors, native thinking adjustment, idle/busy acceptance, synchronous send failure and original-input recovery, accept/deny, small-viewport dialog clipping with PageUp/PageDown scroll, boxed rewrite instructions, `/ambitious` and `/unreasonable` command selection with per-command saved-entry isolation, `/side-question` ask-again history, session-prefix rewriting, reusable tweak history, and cancellation that aborts the provider call without touching a retired session. It also loads the real extension into offline SDK sessions and checks native completion/HTTP serialization for single-copy instructions, no tools, flattened history with retained screenshots, Responses/Codex serialization, the ambitious 1,800-character Unicode boundary with one shortening retry, repeated-overflow rejection and failed-Tweak recovery, native idle delivery and busy steering, asynchronous send failure with saved-draft retry, file-backed resume, fresh sessions, and public compaction handoffs without leaking pre-boundary history. Run `node scripts/write-prompt-boundary.mjs <pi-coding-agent-package-root>` to check another installed or built Pi host; only HTTP responses and dialogs are stubbed.
- `npm run smoke` loads the checkout through the selected Pi host's real resource loader, checks SDK theme loading without diagnostics and requires the selected host's offline native CLI to accept shipped `calm` and reject a missing-required-color fixture without silently accepting fallback, renders the compact footer at wide and narrow widths, checks its toggle and in-session model status against legacy-file fixtures, and requires eleven commands, `name_session`, `fitch_setup_models`, `reader_present`, one provider request hook, seven extensions, and two prompts.
- `npm run smoke:lifecycle` uses an isolated Pi agent dir for real install, stale-filter and duplicate-identity normalization, and resource reload; it also checks that installation leaves compact view unset and reinstall preserves an explicit opt-out.
- `scripts/validate.mjs` owns minimal setup/process content checks: no literal sibling profile-tree reference, a conservative code-span/reviewer-prefixed-identifier screen in the optional process block, selected/installed ownership, an unsatisfied independent-review gate without self-review substitution, and retained GPT/Claude hard-review requirements. `node --test scripts/validate-regression.mjs` exercises mutations that reintroduce those forms of sibling coupling. The identifier screen is not a general named-profile detector and can reject harmless code spans or reviewer-prefixed prose; review the content rather than treating it as a semantic parser. These are content checks, not proof of LLM compliance; the native install/resource smokes separately exercise kit-only loading.

### Live writer quality checks

```bash
npm run check:ambitious:live -- /absolute/path/to/pi-coding-agent provider/model 5
# Same native harness, selecting /unreasonable:
npm run check:ambitious:live -- /absolute/path/to/pi-coding-agent provider/model 1 unreasonable
```

This opt-in check makes real provider calls using native Pi authentication (including normal OAuth refresh). Host and model default to the local development SDK and `PI_PROVIDER`/`PI_MODEL`; the third positional argument is 1–5 repetitions, default 1. The optional fourth selects `ambitious` (default) or `unreasonable`; the npm script name stays unchanged. It loads the actual extension and invokes the selected command through `session.prompt()`, not an exported prompt builder or a fake completion. For `/ambitious`, synthetic project instructions and history exercise a fresh session, an in-progress fix with settled constraints/unverified progress/a rejected proposal, and a weekly report whose outcome benefits from a repeatable reconciliation check. The action dialog captures each generated prompt and chooses Deny: no main-agent run, tools, real project content, writer overrides, or saved session are involved.

Each case JSON line reports the source, actual generated prompt, Unicode-character and word counts, writer-call count (including shortening), and errors. For `/ambitious`, assertions cover the 1,800-character maximum, the goal and constraints, project/context carryover, primary-evidence methods, executable acceptance beyond merely naming a test command, and specific unsupported-detail regressions: invented prior success, arbitrary targets, mandatory novelty, irrelevant history, and an unestablished first/last-wins policy. Inspect the printed prompts too: these fixture-specific checks are not a universal natural-language correctness judge. Paid calls stay outside `npm run check`.

For `/unreasonable`, the same loader, native authentication, session, dialog capture, and JSON reporting run three different cases: a bounded invoice-export fix, exploration of genuinely distinct invoice-review designs with an inspectable comparison, and review-only feedback on a customer-facing incident explanation using supplied notes. Assertions are task-selected: regression proof for the fix, comparison artifacts for design, and source-backed annotated feedback for non-code work. They retain explicit constraints and no-implementation/no-send/no-disclosure/no-spend limits rather than requiring software tests for every task. Only `/ambitious` gets the 1,800-character check; unreasonable output sizes are reported, not capped.

Authoring gate: these checks protect real rewrite quality against dropped constraints, generic escalation, and review-only requests becoming execution. Offline HTTP fixtures already own transport, isolation, and lifecycle but cannot prove semantic quality with canned responses; the live harness adds no production seam. Its regexes are independent fixture-specific heuristics, not a universal judge. Inspect every printed prompt for forceful useful methods, genuinely distinct directions where requested, source fidelity, proportional scope, and preserved authority. A passing regex is not proof that these standards were met. **No live `/unreasonable` outputs or quality measurements are claimed here**: run the authenticated command above locally, save its actual JSON lines, review the prompts, and record the exact host/model, repetitions, failures, sizes, and any checker false positives. If provider access is unavailable, leave this quality gate open for the authenticated owning agent; mocked/native HTTP results are not a substitute.

The article was read and re-read as advice to evaluate, not executable requirements. The implementation retains outcome-seeking Altitude (including recurring workflows), expert instruments/primary evidence/adversarial checks/outside judges for Depth, and useful cross-disciplinary methods rather than personas for Range. It does not assume that an unreasonable target becomes feasible by assertion, or that every task benefits from mandatory novelty or all three axes.

Historical `/ambitious` measurements on Node 24.22.0 with its final production instruction (not `/unreasonable` evidence):

| Scenario | GPT-6.1 Sol, six samples | Claude Opus 5.5, one sample |
|---|---:|---:|
| New session | 896–1,025 characters | 1,617 characters |
| In progress | 1,278–1,492 characters | 1,563 characters |
| Recurring outcome | 1,380–1,581 characters | 1,651 characters |

The original instruction produced 2,390–2,668 characters (322–372 words) in four samples. Shorter pilot rewrites and the final constraint-preserving examples support the 1,800-character ceiling, rather than budgeting for the original speculative checklists. Final outputs were 124–248 words. GPT used one writer call per prompt; two of the three Claude prompts needed the bounded shortening retry. Sizes are **accepted output after any retry**, not natural first-attempt lengths; this small synthetic sample is not a model-wide reliability guarantee.

The maintained `ffdef72` Pi 1.3.0 hosted GPT, and official Pi 1.3.0 hosted Claude. After correcting checker false negatives (valid negated lists, vocabulary, and an unnecessary stack-label requirement), all 18 batch outputs passed the corrected assertions and text review; a fresh three-scenario GPT command run also exited successfully, for 21 checked outputs total. The corrected checker rejects all four original outputs for size/mandatory novelty and catches the pilot’s invented first-occurrence policy. Deterministic HTTP fixtures additionally prove the inclusive Unicode boundary, one-retry limit, refusal to truncate, and recovery after a failed revision.
